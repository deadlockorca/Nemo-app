Nemo Admin — đăng nhập + quản lý khách/key/thiết bị (local)

Đã làm:
- Next.js App Router + TypeScript + Tailwind CSS.
- Trang đăng nhập tại /, nhận tên đăng nhập hoặc email.
- Trang tổng quan /admin kiểm tra phiên ở server trước khi đọc dữ liệu.
- Đăng xuất thu hồi phiên trong MySQL.
- Mật khẩu băm scrypt; token phiên ngẫu nhiên chỉ lưu bản SHA-256 trong DB.
- Phiên hết hạn sau 12 giờ; cookie HttpOnly, SameSite=Lax, Secure khi production.
- Chặn POST khác Origin; tối đa 5 lần thử / tên đăng nhập / 15 phút.
- Dashboard đếm dữ liệu thật, nhật ký đăng nhập.
- Migration cho admin, phiên, khách, key, thiết bị, nhật ký.

QUẢN LÝ ĐÃ CÓ
/admin/customers: thêm, sửa khách; tên, liên hệ, ghi chú; tìm kiếm, phân trang.
/admin/licenses: cấp key (mặc định 30 ngày), lọc trạng thái, gia hạn, thu hồi.
/admin/devices: xem thiết bị, gỡ liên kết để chuyển máy, giữ nguyên hạn key.
/admin/activity: xem lịch sử gồm người thao tác, thời gian, mã, chi tiết.
API quản trị /api/admin/* yêu cầu phiên admin; POST/PATCH kiểm tra Origin.

QUY TẮC KEY
- Key mới ở trạng thái active ngay khi cấp cho khách: activated_at = giờ UTC DB,
  expires_at = thời điểm cấp + số ngày đã chọn. Chưa cần gắn thiết bị để tính hạn.
- Key đầy đủ chỉ xuất hiện một lần lúc cấp; database chỉ lưu SHA-256 + 8 ký tự cuối.
- Nếu mất key chưa giao: thu hồi và cấp key mới. Không có chức năng xem lại key.
- Gia hạn key pending cũ: thêm thời lượng chưa kích hoạt (tối đa tổng 3650 ngày).
- Gia hạn key active: cộng số ngày vào max(hạn hiện tại, giờ UTC của server).
- Key revoked có nút Khôi phục; giữ nguyên hạn cũ và liên kết thiết bị hiện có.
- Key pending cũ được khôi phục về pending; key đã bắt đầu tính hạn trở về active
  (giao diện vẫn hiện Hết hạn nếu hạn cũ đã qua). Không cộng ngày khi khôi phục.
- Cần khôi phục trước khi gia hạn key revoked. Mỗi thao tác có kiểm tra version
  và nhật ký. App đã đăng ký có thể mở lại để xác thực, không cần nhập key lại.
- Gỡ liên kết thiết bị không đặt lại ngày kích hoạt hay ngày hết hạn.
- Thao tác gia hạn/thu hồi/gỡ thiết bị có transaction, row lock và kiểm tra version.
  Nếu hai tab thao tác cùng bản ghi, yêu cầu cũ bị từ chối (409), cần tải lại.
- Có nút Xóa key với xác nhận: xóa vĩnh viễn key và gỡ liên kết thiết bị; giữ
  lịch sử thao tác. Key đã xóa không thể khôi phục. Không có nút xóa khách.
- Mỗi trang 25 bản ghi; tìm tên khách khi danh sách chọn có nhiều hơn 25 khách.

ĐÃ CÓ API CẤP PHÉP
POST /api/v1/challenge, /api/v1/activate, /api/v1/verify.
Thiết bị chứng minh giữ khóa riêng Ed25519 bằng thử thách hết hạn sau 5 phút.
Giấy phép EdDSA/JWT, tối đa 24 giờ và không vượt hạn key; gợi ý kiểm tra mỗi giờ.
Key mới tính hạn từ lúc cấp trên web; nhập key chỉ gắn thiết bị, giữ nguyên hạn.
Key pending cũ vẫn theo quy tắc tính hạn từ lần kích hoạt thiết bị đầu tiên.
Chặn thiết bị khác, key hết hạn/thu hồi, thử thách đã dùng và chữ ký giả.
Khóa ký private chỉ nằm trên server, trong file quyền 600, đường dẫn qua env.

TRÊN AAPANEL (CHƯA THỰC HIỆN)
1. Dùng MySQL 8.0+ (không mặc định coi MariaDB tương đương).
2. Tạo database riêng + user riêng. Không mở MySQL ra Internet.
3. Cấu hình biến môi trường theo .env.example:
   APP_URL=https://nemoapp.duckdns.org
   DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD theo aaPanel.
4. npm ci; npm run db:migrate; npm run admin:create.
   npm run license:keygen /duong-dan-rieng/license-keys
   Đặt LICENSE_PRIVATE_KEY_FILE=/duong-dan-rieng/license-keys/private.pem.
   Khóa private ngoài public/webroot, chỉ user Node đọc được; sao lưu riêng.
   File public.pem phải được pin trong client trước khi phát hành.
   npm run build.
5. Chạy Node.js 24 bằng process manager aaPanel:
   npm start -- --hostname 127.0.0.1 --port 3000
6. Nginx reverse proxy tới 127.0.0.1:3000, giữ Host và chuyển tiếp Origin nguyên gốc.
   Giữ các header Set-Cookie, Cache-Control; không cache trang quản trị.
7. HTTPS chứng chỉ hợp lệ, tự gia hạn. APP_URL khớp URL truy cập thực tế.
8. Đặt giới hạn request đăng nhập theo IP tại Nginx (bổ sung cho giới hạn tài khoản).
9. Sau migration, user runtime chỉ cần SELECT/INSERT/UPDATE/DELETE;
   có thể dùng user migration riêng có quyền CREATE/ALTER/INDEX/REFERENCES.
10. Sao lưu database định kỳ và cất khóa ký giấy phép riêng; không tạo lại khóa mỗi lần deploy.

Nếu dùng output standalone: sao chép public và .next/static vào đúng vị trí
trong .next/standalone trước khi chạy server.js. Dùng npm start với đầy đủ
project thì không cần bước này.
