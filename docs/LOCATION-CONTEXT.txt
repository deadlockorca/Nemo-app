GLOBAL PILOT GATES (new runtime env; neither configured means disabled)
LOCATION_CONTEXT_ENABLED=false
LOCATION_CONTEXT_PILOT_LICENSE_ID=<exact numeric license ID, not employee code>
Set enabled=true only for the agreed pilot after checks. Endpoint authorizes
exactly one allowlisted license. A future multi-customer rollout must explicitly
replace this single-license gate; do not silently enable every legacy customer.
Switch global enabled=false or disable the individual policy to deny subsequent
requests, including retries with cached server responses. An already-returned
response cannot be remotely erased: validity is capped to 60 seconds and the
client must bind it to one action, never persist it for later actions.

DEVICE API
POST /api/v1/location-context (separate from Nemo's business server)
Content-Type: application/json
Authorization: Bearer <existing valid signed license lease>
X-Nemo-Timestamp: <Unix seconds, 10 decimal digits, within 60 seconds>
X-Nemo-Signature: <Ed25519 signature, base64url without padding>

Body example (UUIDs must be real lowercase UUIDs):
{
  "requestId": "a5bd861e-4fc4-4139-8a44-9a248c21865a",
  "sessionId": "39faf36a-f46a-48c2-b64d-d91d95b5cb72",
  "action": "start",
  "hospitalId": "102175",
  "employeeUsername": "12436899"
}

sessionId: fresh random UUID for each authenticated login session, discarded on
logout/account change. requestId: fresh per button action; retry uses same ID.
action: start|end. hospitalId: actual app action's ID, not display name/code.
Unknown body fields rejected. Body limited to 4096 bytes, no query credentials.

Signature input is the exact UTF-8 bytes, with literal LF between these lines
and NO additional LF after the body:
nemo-location-context-v1
POST
/api/v1/location-context
<X-Nemo-Timestamp>
<exact raw JSON body>

Sign with the same device private key used for license challenge proofs. Do not
export that private key, create a different identity, or reserialize after signing.
Server verifies existing lease signature, live license status/version/expiry,
current device binding and request signature before checking employee/policy.
Username check is an admin binding plus a device-authenticated declaration; it
is NOT independent proof of a successful/current Nemo login. That binding must
be enforced by the iOS integration from a verified successful session. Do not
use typed login form text or stale preferences as proof of the active account.

Response 200:
{
  "requestId": "...", "sessionId": "...", "action": "start",
  "hospitalId": "102175",
  "center": {"latitude": 21.0337507, "longitude": 105.7788244},
  "radiusMeters": 120,
  "serverTime": "<UTC ISO>", "expiresAt": "<UTC ISO>"
}
No employee username, license token or device credentials in response.
Expiry <= 60 seconds, lease expiry and license expiry.
Successful retries return the same response, but only after current authorization
checks. Reused request ID with changed context/config -> 409. Expired ID -> 409;
never silently turn retry into a fresh action. Used IDs retained for one day.
Max 30 newly accepted contexts/minute/license; retry does not consume another
slot. All responses no-store; errors contain code only, no raw request logging.
Configure reverse proxy rate limiting for unauthenticated/invalid request floods.
