MÔI TRƯỜNG
Node 24.x, MySQL hiện hành và Python 3.11+. Ubuntu/Debian cần g++, make,
pkg-config, libssl-dev, openssl, git, python3-venv. Chạy ứng dụng và worker bằng
user riêng, không chạy root. Các đường dẫn dưới là mẫu, cần khớp VPS thực tế.

1. Tạo release mới, cài npm ci (có tsx để chạy worker); chưa đổi release live.
2. python3 -m venv /opt/nemo/python
   /opt/nemo/python/bin/pip install -r scripts/ios/requirements.txt
3. sh scripts/ios/build-zsign.sh /opt/nemo/zsign
   Build từ commit cố định 9299685bab7ef99827e06e5dfda93af747386590 của
   https://github.com/zhlynn/zsign (MIT), phiên bản 1.1.3. Không lấy nhánh latest
   hoặc tệp binary do khách upload. Cài bằng user có quyền ghi thư mục đích.
4. Bổ sung biến runtime, giữ nguyên biến DB/khóa license hiện hành:
     APP_URL=https://<tên-miền-thật>
     INSTALL_STORAGE_DIR=/var/lib/nemo/installations
     INSTALL_STORAGE_KEY=<32 byte ngẫu nhiên, 64 ký tự hex>
     IOS_SIGN_PYTHON=/opt/nemo/python/bin/python
     IOS_SIGN_BACKEND=zsign
     IOS_ZSIGN_BIN=/opt/nemo/zsign/bin/zsign
   Web và worker cùng dùng DB, kho tệp và khóa mã hóa. Kho 0700/tệp 0600;
   sao lưu INSTALL_STORAGE_KEY riêng cùng các tệp đã mã hóa. Không đổi khóa này
   khi đã có chứng chỉ lưu trong kho nếu chưa có bước chuyển mã hóa.
5. Sao lưu DB và cấu hình live; kiểm tra rollback rồi chạy db:migrate bằng
   chính cấu hình VPS. Không chép schema/data local đè lên DB hiện hành.
6. npm run build (postbuild kiểm tra standalone không chứa bí mật).
   Bật thử trên cổng nội bộ riêng; kiểm tra đăng nhập/API key cũ và key test
   mới trước khi chuyển reverse proxy. Nếu cần rollback code, giữ bảng mới;
   không xóa bảng/drop DB hoặc phục hồi DB gây mất các request mới.
7. Nginx/aaPanel: HTTPS tin cậy, proxy đúng APP_URL; upload ít nhất 160 MB,
   timeout kiểm tra tệp đủ dài; không cache API, manifest, IPA có token;
   không đưa kho chứng chỉ vào webroot và không ghi URL bearer vào access log.
8. deploy/nemo-signing-worker.service là mẫu systemd. Sửa User/Group, đường
   dẫn Node/release/env và ReadWritePaths đúng thực tế trước khi cài. Worker
   phải chạy bền và tự khởi động lại; không chạy ký trong request Next.js.
9. Dùng key thử riêng trên VPS, profile đúng UDID, nhập mã -> ký -> tải manifest
   và IPA qua HTTPS. Xác nhận cài/mở trên iPad thật và kích hoạt lấy đúng hai ID.
   Kiểm tra một key cũ vẫn hoạt động; chỉ khi đạt mới mở luồng cho khách mới.

KIỂM TRA KÝ LINUX
Helper chọn zsign trên Linux khi IOS_SIGN_BACKEND=auto; macOS vẫn chọn Apple
codesign. Có thể ép zsign trên Mac để đối chiếu. Tệp private key tạm 0600 nằm
trong thư mục riêng, xóa sau lời gọi công cụ; không đưa password upload vào
argv/log. Gói chứng chỉ lưu lâu dài vẫn được bọc AES-256-GCM.
Sau ký, verify.py kiểm tra CMS/chuỗi Apple, signer đúng profile, SHA256 từng
trang mã, các special slot, entitlements XML/DER, và resource seal của các bundle.
OpenSSL không hiểu các critical role marker của Apple: chỉ cho phép danh sách
OID xác định, từ chối critical extension khác trước khi dùng -ignore_critical.
Không dùng -noverify, không bỏ kiểm tra profile CMS hoặc UDID.
Cuối cùng so mã/dữ liệu Mach-O và tài nguyên với IPA gốc; chỉ chữ ký và
embedded.mobileprovision được đổi. Bộ kiểm tra cố ý hỗ trợ cấu trúc IPA trắng
hiện tại; cấu trúc/hash/signature format lạ sẽ bị từ chối thay vì cho qua.
